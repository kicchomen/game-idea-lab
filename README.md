# Game Idea Lab

Small, dependency-free playable experiments. No build, CDN, account, or analytics required.

## Sensor Shift

Open `games/sensor-shift/index.html` on any static server. GitHub Pages path: `/game-idea-lab/games/sensor-shift/`. 

Embed: iframe width 100%, height 1040px (scrolling allowed), title `センサーずらしを試遊`. Checked iframe widths: 320px, 390px and 500px (desktop browser; no physical phone test). The board preserves its 420×480 aspect ratio. Page has a maximum width of 500px. Use a full-screen link alongside the iframe. Local trial history may be unavailable in third-party iframes; the game works without storage.

Controls: change the sensor angle (−45° to +45°, 1° increments), press 再生, observe the blue/red ray and orange turn markers, then change the angle and replay. Buttons also permit single-degree adjustment. Pause/resume/reset supported. Last 8 completed trials are stored only in this browser.

## Mechanics

The robot moves at 90 units/second. A ray points at `heading + sensor angle`. When a wall is within 100 units, the robot turns right exactly 90°. The detector re-arms after its reading exceeds 104 units. Physics runs at 120 fixed steps/second, independent of display frame rate. Touching a wall with the radius-9 body fails. Entering the exit with the robot center succeeds. A trial ends after 12 simulated seconds. There is no goal attraction or angle-specific scripted route.

The prototype implements only the distance-sensor-angle part of the original concept. Light sensors, floor sensors, sensor-position changes, stage progression, and completion scoring are intentionally outside this experiment.

## PDCA iteration 1

Plan: create a single adjustable distance ray and a fixed right-turn robot.
Do: first layout had 400 units of vertical space, a bottom wall at y=392, and an exit starting at y=340.
Check: sweep of −45° to +45° produced no successes. Even trajectories clearing the obstacle detected the bottom wall before reaching the exit and turned away.
Act: enlarge vertical space to 480 units and move the bottom wall to y=472, leaving the robot, sensor, obstacle, exit and turning rule unchanged.
Re-check: 0° still collides; −40°, −35°, +35°, +40° reach the exit under the exact same physics. The test also asserts every step remains exactly 0.75 units, so success cannot be produced by goal snapping.

Next playtest question: can a first-time player explain why moving the sensor changes the turning point? Observe confusion around the re-arm rule and record it before adding new sensor types.
