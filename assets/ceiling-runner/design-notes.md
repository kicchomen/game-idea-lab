# 天井走りの点検ロボ — 企画と試作（2026-11-24 JST）

## 遊びの狙い
重力に振り回される通路を、ロボが床・天井どちらも通り道に変える。先を見る → 反転を決める → 前進しながらレールを渡る → マーカーを拾う。操作は小さく、決めた時点と切り抜けた時点がずれるのが核。スタート後に行動を編集して再生するゲームではない。

### 既存案との照合
参照 main: `d4069285662c2818d7baf6c423dc9be8e7b64756`（2026-11-24 の GitHub refs と README、games、index、および既存公開台帳を照合）。
- 星灯りの屋根わたり: 左右移動・ジャンプ・空中ダッシュで屋根を渡り、3灯りを集めて灯台。横見・アクション・収集要素は近い。今回は横移動を操作せず反転のみ、独立した床・天井レール、移動度の猶予、反転中に通る中央、最低回収数 vs 全回収の判断が違う。
- 山あいの綱渡り: 横方向バランス操作で姿勢が傾きすぎないように進む。反転でレーンを選ぶ今回とは主動詞・失敗条件が違う。
- 岩壁のふたつの手: 2本の手を個別に管理し、次のホールドに交互で手を出す。今回の一定速度・反転できない移動時間とは異なる。
- 渓流の糸つかい等、タイミングを読む既存作品はあるが、床・天井の往復で進行中に接触を避ける例は main で確認できない。前日の未公開「山小屋の電気当番」は電力の配分とターン管理であり、別成果物として扱う。
- Blogger の公開フィード44件を照合し「天井走り」「点検ロボ」の重複なし。「山小屋」も公開フィードなし。Blogger 管理画面の下書きは未確認。

### 5〜10秒 / 10分 / 1時間
- 最初の5〜10秒に、画面端から近づく障害物を見て1回反転し、天井に貼り付く納得感を狙う。何もしないと最初の障害で約1.76秒に失敗する。
- 本編の10分では、最低4個で安全に通す／6個満点に挑む、中央の障害を見て待つ、同じ道でも切替タイミングを変える。試作は約13秒の固定コース1本なので、10分の反復性を実証していない。
- 1時間を支える展開案は、往復で使えるレールが変わる保守区画、回収を行きにするか帰りにするか、反転先で別の区画へ分岐する設計。固定コースの追加だけにしない。これらは未実装。

## 試作済み
約13秒の固定1コース、自動前進、レール着地時だけ反転、ダイヤ形マーカー6個、中央・床・天井の抵触判定、最大6個のうち4個で通過、衝突／不足の両失敗、再挑戦、ポーズ、キーボードとタッチ。アカウント・広告・外部スクリプト・ネットワーク利用・保存・音声なし。画像は記事用の生成カバーと、操作の仕組みの自作図。図はプレイそのものの画面ではない。

## 検証と改善
1. 計画: 反転中にも前進するため、見てから意思決定が間に合うことを重視。
2. 試作: 反転の乗り換え速度 172 座標/秒、横81座標/秒。中央障害2点を配置。スマホ風表示でも先が見えるよう最低237ワールド単位の画角と、レールを中央より左に固定。
3. 検査: エンジンは固定120Hz。6/6と4/6それぞれの走行、反転タイミング6箇所の ±0.1秒全64端点、入力なしの失敗、リトライなどを確認。
4. 改善: 独立レビューで、一時停止をボタンで操作し Escape で再開した後、Space が反転ではなく一時停止を再発動する不具合を検出。再開時は反転ボタンへフォーカスを戻すようにし、模擬 DOM で修正を再検証。レール着地時の反転矢印は非表示として盤面外描画を改善。 初回の失敗時に少し手前で反転するヒントを表示する。残り距離・回収数・引力方向をラベル付きにする。停止・成否・やり直しで盤面位置を変えず、ボタン群が画面外へ移動しない設計とした。
5. 回帰検査: 公開 main HEAD のアーカイブに今回の対象ゲームだけを追加し、全1215/1215合格（既存1193、本体13、独立9）。ブラウザではなく Node / 模擬 DOM の検査。
6. 要確認: 初見5秒以内に反転を理解できるか、端点に合わせなくても十分な猶予があるか。完成版の実ブラウザ単独/埋込、Bloggerプレビュー/公開後、スマホ実機は個別の検査で記録し、エンジン結果と混ぜない。
