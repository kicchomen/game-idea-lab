# 屋台の鍋番 — 体験設計と試作 / 2026-10-29

## 役割と主な遊び
小さな屋台で、煮える速さの違う3品を、温かい一皿にそろえる鍋番になる。主動詞は **入れる時刻をずらす・共通の火を変える・取り出す・まとめて出す**。火は全食材に共通で、取り出した結果は戻せず、先に盛付けた食材は冷め始める。1品ずつよくできても、1皿として出す時刻が合わなければ成功しない。

時間を一手ずつ進める案も比較したが、秒を待つ間に他の食材が同時進行する感覚を今回の核とし、リアルタイムを選択。反射の速さだけを求めないよう初皿は適正帯を5単位に広げ、一時停止、火止め、一斉盛付を認める。初見の人に適した難度かは未検証。

## 想定体験の広がりと限界
- 最初の5〜10秒：大根を入れ、他の食材の必要値を見る。同じ火でも途中投入なら追いつくことに気づく狙い。
- 10分の仮説：弱火で余裕を持つか強火で短時間に仕上げるか、火を止める位置、同時盛付と適時取り出しの違いを3注文で比較する。固定手順を記憶すれば簡単になる。人による10分の面白さは未確認。
- 1時間の構想（未実装）：複数注文を受ける/断る判断、食材の共通仕込み、屋台の設備選択、2人で調理と配膳を分担し会話する遊び。単なる食材数の追加でなく、工程合流の単位と分担責任が変わる展開を想定。

## 正確な試作ルール
食材は毎回 **大根・じゃがいも・葉物**。数値は架空のゲーム内火入れで、実際の調理時間・食品の安全性の指南ではない。

| 注文 | 各食材の適正火入れ（大根 / じゃがいも / 葉物） | 取り出し後の温かさ期限 | 注文の制限 |
|---|---|---|---|
| 1皿目 | 30–35 / 18–23 / 4–9 | 10秒以内 | 46秒 |
| 2皿目 | 28–32 / 16–20 / 5–9 | 9秒以内 | 42秒 |
| 3皿目 | 32–36 / 20–24 / 6–10 | 8秒以内 | 44秒 |

- 待機中は何も進まない。「調理を始める」で弱火から開始。食材はまだ鍋外。
- 弱火は鍋内全品の火入れを毎秒1、強火は毎秒2増やす。止めると増えない。火は共通。投入した食材だけが加熱される。
- 食材ボタンは「入れる」→「取り出す」→盛付済み。取り出した瞬間の火入れで不足/適正/煮すぎを固定。再投入・再加熱・Undoなし。
- 3品がすべて盛付済みで提供できる。全品が適正で、各品がその皿の温かさ期限以内なら成功。期限ちょうどは許可、超過は冷めた扱い。
- 火止め中も注文時間と皿上の冷却は進む。一時停止は火入れ・冷却・注文時間をすべて止める。
- 制限時刻に達するとその皿は不成功。未盛付の品も明示。提供が完了した皿は時間停止して結果を読める。
- 不成功でも次の注文へ進む。3皿後に全体判定、2皿以上成功で屋台の仕事完了。最終画面から最初から再挑戦。
- 途中リスタートは確認を挟み、その間は一時停止。取消は元の調理状態へ。画面を離れた場合は明示的な再開を待つ。

## 技術境界
既存の依存なし静的HTML/CSS/JSを継承。pure engine.jsが状態・経過・品質・得点を所有し、DOM app.jsが入力と描画を担当。読みやすい数値と3食材の工程が中心なので、外部ランタイムやビルド依存は増やさない。自作CSSの鍋と皿、文字記号の食材を使用。操作ボタンは44px以上。キーボード1/2/3、Q/W/E、P、Tab/Enter/Spaceとタップに対応。

requestAnimationFrameで活動中の時間を積算。0.75秒以内のフレーム間隔は経過時間を全量反映し、0.75秒を超える中断は自動pauseとして突然の失敗を避ける。独立レビューで0.1秒切捨てによる低FPS時の遅れを発見し、全量反映へ修正した。非表示/blurもpauseし、勝手に再開しない。作者テストのsimulationと実ブラウザーの操作は別。

ネットワーク・アカウント・保存・広告分析・音声・注文乱数・人間以外との対戦・衛生判定はない。再挑戦で注文順/数値は変わらない。

## PDCA
1. 初期案12/8/4と温かさ10秒では、全部同時投入して完成順に回収しても冷めず、投入順の工夫が不要。独立企画レビューの指摘を受け、初皿30/18/4に変更。
2. 狭い適正帯では単なる反射検査になりやすいため、初皿+5単位、後半+4単位へ。火を止めてから3品を一斉に取り出す方法を正規の成功手順として残した。
3. 観察可能性を上げるため経過秒/残り秒と実火入れ数値、適正帯、盛付後残り温かさを表示。画面の単純な丸めで29.99が30.0に見える誤解を避け、火入れ表示は小数第1位へ切り捨て、適正状態も文字で併記。
4. 3食材の操作が分断されないよう、鍋/皿の視覚領域を85〜90pxに圧縮。実ブラウザーの狭幅検査結果は親担当が別途記録。

### 作者による方策検査
各皿、弱火/強火それぞれで、必要値の差に合わせた投入時刻→最長品の下限で火止め→全回収→提供は成功（計6パターン）。

一方、全部同時投入し、葉物を適正範囲の最後まで待って回収、最長品を最速で仕上げる方策でも全3皿×弱/強の6条件で冷め失敗。初皿強火では葉物9単位時点4.5秒に回収、大根30単位時点15秒に完成し、間隔10.5秒が温かさ10秒を超える。火を途中で止めると完成時刻はさらに遅くなるため、同時投入ではこの差を短縮できない。再加熱もない。

これは限定したモデルの性質であり、人の面白さ、教育効果、現実の料理技能は保証しない。投入時差を一度覚えると反復の意義が減る点は未解決の限界。

## 実ブラウザー確認用の操作例
初皿弱火：調理開始→大根を入れる。大根の火入れ12前後でじゃがいも、26前後で葉物を投入。大根30以上・じゃがいも18以上・葉物4以上を確認して火を止める。3品を取り出し、10秒以内に提供。許容帯を見て多少の時刻差を吸収する。

初皿強火：開始→強火→大根。大根12単位時点（投入から約6秒）でじゃがいも、26単位（約13秒）で葉物、30単位（約15秒）以降で火止め。全回収→提供。

2皿目弱火の投入差は0/12/23秒、28秒以降に火止め。3皿目は0/12/26秒、32秒以降に火止め。強火なら各差を半分にする。画面の火入れ数値と適正表示を優先し、ツール処理や時計の推測だけで成功を判断しない。

失敗例：何も入れず制限まで待つ、開始直後に全品入れてすぐ全品取り出す（不足）、全品を強火にかけ続ける（煮すぎ）、適正で取り出したあと温かさ期限を超えて提供（冷め）。
