# ブラウザーQA

このファイルには隔離したheadless Chrome/Chromiumによる、ローカル静的ページのブラウザー操作を記録する。自動化したブラウザー結果は実機操作や初見ユーザーによるプレイテストと区別する。

## 主要フロー

- 最初の数量を実際のポインター入力で提案。ミナの−1拒否、タロウの+3同意、しんぼう3/4と具体的な2地図↔2水筒の再提案を確認。
- 実際のダブルクリックで、提案への拒否が一度分だけ進むことを確認。
- 再提案ボタンを実際の Enter で起動し、両者の同意へ進むことを確認。Spaceによる起動も確認。
- 旅人の再提案を適用し、受諾と取り引き成立を確認。
- 2組目で追加交渉を選択、数量を変え、双方が同意する新条件を提示。
- 3組目で条件を拒否され続ける失敗を確認し、ルート結果後に最初から再挑戦。
- 別のフローで3組すべてを決裂させ、0/3の失敗結果と再挑戦後のしんぼう4/4を確認。
- 下限数量にする実ブラウザーのEnter操作後、無効化された−ボタンではなく同じ品の有効な＋ボタンにフォーカスが移ることを確認。
- 成立後にEnterで再交渉を開始した時、disabledの再提案ボタンではなく最初の有効な数量操作にフォーカスが移ることを確認。
- 決裂後の条件パネルが「最後に提示した条件です。」と表示し、合意済みの文言を出さないことを確認。

## レスポンシブと操作

孤立したheadless Chromeで、320 / 360 / 390 CSS pxの表示幅を設定。文書のscrollWidthとclientWidthが各幅で一致。数量ボタンは44×44px、主操作は48px高。コンソールエラー、ページ例外なし。アクションを含む主要な成功・失敗・再挑戦フローとスクリーンショットは、デスクトップChromium内の実操作で確認。

Blogger記事の16px左右余白により、320px記事幅ではゲームのiframe内側が286pxになることを発見。ゲーム側の320px最小幅を外した後、ローカル静的ページを286 / 320 / 360 / 390 CSS pxで確認。各幅で文書幅が表示幅と一致し、数量調整は44×44px、主操作は48px高。スタイル・エンジン・コントローラーのURLには `?v=20261022-2` を付けた。
